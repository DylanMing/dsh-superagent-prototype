# 000 理念

> [English](000-philosophy.md) | 中文

dsh-superagent 是一个框架，也是一种与智能体协作的方式。它的核心原则是：

**尽可能少占用人的注意力，尽可能多地交付价值。**

项目中的每一部分都按它消耗的注意力来评判。一条消息、一条通知、一个问题、一项设置、一个面板元素和一段文档，各自都在消耗某个人的注意力；每一处都必须提供超过这份成本的价值，否则就删掉。

## 这对智能体意味着什么

- **只在被要求时行动，或在成文规则允许时行动。** 一个请求要算数，必须直接指向智能体，并且来自团队允许的人：允许名单上的人，或团队已开放接收请求的对话中的任何人。没人要求的工作，需要团队写下的规则，并且以只记录“智能体本来会做什么”的模式启动。
- **只在有人必须行动、或有人能用上结果时才开口。** 它对请求确认一次，并说明自己将做什么。工作时保持安静。结果就绪时、需要某个决定时、或无法完成时才再次发言。消息简短，并发送到发起请求的那个对话。
- **一次只问一个具体问题**，以结构化形式提出，让问题真正到达人那里，而不是留在一份长报告里。
- **按影响范围止步，而不是按投入多少止步。** 局部改动做到可评审的结果为止。需要设计决策的改动，以一个明确的问题停下。
- **如实汇报。** 草稿标明未完成，失败就报告为失败，绝不为省去提问而绕过限制。

## 这对设计意味着什么

- **概念要少。** 设计里只有它的领域概念（例如来源 Source），以及这些概念的具体实现（例如 GitHub 和飞书 Feishu）。一个业务需求要么变成其中某个概念的属性，要么变成智能体遵循的提示词。设计不会为它新增概念。
- **设置要少。** 当一个取值几乎适合所有团队时，用默认值取代设置项。团队用文字描述的行为属于提示词文本，不是设置项。
- **面板只显示需要人处理的内容。** 它首先列出等待人处理的事项。健康状态不占空间。
- **文档按顺序阅读。** 每篇编号文档只建立在它之前的文档之上，读者永远不需要尚未介绍过的概念。

## 责任

智能体以团队每天都看到的账号发表评论、发起拉取请求（pull request）、给人发消息。它发出的每一条消息都在消耗同事的注意力，而你要为此负责。智能体能做的事越多，操作者对团队应尽的谨慎就越多：

- **从窄开始。** 先从一个很短的允许名单开始，主动工作只做记录。等“智能体本来会做什么”看起来正确之后，再放宽这两者。
- **为减少噪音而调整。** 智能体太吵时，把它的提示词写得更短、更严格，或者暂停它。不要增加更多消息去解释这些噪音。
- **不要用它制造数量。** 批量拉取请求、群发消息和无意义的忙碌，给团队带来的负担大于收益。
- **对它说的话负责。** 读一读智能体以你的名义发布的内容，发现不对就去改提示词。

目标是：在对的时间给出对的帮助，其他时间什么都不做。
