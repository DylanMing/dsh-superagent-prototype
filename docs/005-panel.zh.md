# 005 面板

> [English](005-panel.md) | 中文

在 DeepSeek Harness Web 的侧边栏打开 **Superagent** 即可监督代理。面板优先呈现需要人处理的工作，其次是系统健康状况和历史。本文档建立在 [000 理念](000-philosophy.zh.md) 到 [004 提示词](004-prompts.zh.md) 的基础之上。

## 三个问题

打开面板会按以下顺序回答三个问题：

1. 现在有需要我处理的事吗？
2. 系统是否健康、是否在做该做的事？
3. 一件工作从触发、经评估到任务的历史是怎样的？

## 标签页

标签页跟随工作流：**Overview**（概览）、**Source**（来源）、**Trigger**（触发）、**Eval**（评估）、**Execution**（执行）和 **Settings**（设置）。在仓库和账号设置成功之前，Overview 会显示缺什么，并链接到相应的设置。

| 标签页 | 显示内容 |
| --- | --- |
| Overview | 需要处理的任务、系统问题、最近 24 小时的活动计数，以及执行器负载。每个区块都链接到其详情页 |
| Source | 来源状态、设置问题和非零计数。被过滤的触发和被丢弃的消息覆盖与 Overview 相同的 24 小时窗口 |
| Trigger | 可按 Subscribed（已订阅）、Evaluating（评估中）、New Triggers in 24 h（24 小时内的新触发）或 All Threads（全部对话线程）筛选的对话线程。每个对话线程按最新在前显示其触发、决策（Decision）和订阅 |
| Eval | 决策及其理由和匹配到的规则 |
| Execution | 执行器状态、Pause processing（暂停处理），以及可按 Open（未结束）、Pending（待处理）、Working（工作中）、Waiting for a Trigger（等待触发）或 Ended（已结束）筛选的任务。任务详情显示操作、授权、等待中的输入、订阅和派发 |
| Settings | Sources（来源）、Eval（评估）、Execution（执行）、Prompts（提示词）和 Deployment（部署）。每个分组都包含其保存历史 |

### 阅读单条记录

被丢弃的消息会链接到它的任务；若它没有任务，则链接到它的对话线程。Source 页面会说明是该对话消失了，还是来源停止监听它。

仍由执行器拥有的人工后续消息会被标记为 **Delivered to Ticket**（已投递给任务），且不经过评估。对话线程还会显示交回理由和仅用于上下文的订阅。**Evaluate again**（重新评估）可以把该后续消息送入评估，或重试一个没有有效裁决的触发，即被其来源过滤掉的触发、评估不可用的触发，或已投递但既没有不停工的决策、也没有执行器确认回复的消息。

任务详情显示发起的触发、决策及理由、范围以及 Policy 版本。派发和次要细节折叠在即时操作之下。当输入投递失败，或任务在受阻/失败报告之后等待人时，提供 **Retry**（重试）。已结束的任务会显示结果，例如 **Pull request merged**（拉取请求已合并）或 **Stopped by a person**（被人停止）。

## 设置分组

- **Sources：** 每个来源一张卡片，含其开关、字段和已验证的账号信息。GitHub 还提供针对新 Issue、拉取请求、评论和默认分支 CI 的“全部接收”开关。轮询与读取上限在 Advanced（高级）下。
- **Eval：** Policy 版本与规则，其后是 **On each Source**（按来源）和评估设置。每个来源标签页包含其允许列表、成员同步、准入表和机器人列表。同步在启动时运行，也由 **Sync now**（立即同步）触发。准入表区分接收范围、发送者是否属于成员，以及消息是否指向代理。评估设置用于选择接受模式、超时和评估模型。
- **Execution：** worker 模型、并发、目录根、准备命令和被禁用的命令。点击某个可用变量会把它插入准备命令。
- **Prompts：** **Edit**（编辑）可修改团队小节、内置部件和技能。**Full prompt**（完整提示词）显示组装后的文本，并与已保存文本或默认值对比。**History**（历史）列出各版本。被编辑过的内置部件会标记为已更改，并可重置；模板会列出其必需的占位符。

  若某次升级改变了被覆盖的默认值，会把它标为 **Default updated**（默认内容已更新）。面板会在团队文本上方对比新旧默认值。如果旧默认值没有记录，则改为对比团队文本与新默认值。可选择 **Keep my text**（保留我的文本）或 **Use the new default**（使用新默认值）。已移除部件的覆盖列在标签栏下方，并在下次保存时丢弃。
- **Deployment：** 启动问题（附 **Check again**（重新检查））、状态目录和机器限制。已保存的限制无需重启即生效。DeepSeek Harness 的 Plugin Manager 会暴露同一个页面。

## 搜索

页头搜索可按文本、id、Feishu 消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。原始消息中缺失的 Feishu 链接，只有在宿主于当前进程生命周期内读取过它之后才可被搜索到。

搜索也能按 `#12` 或 GitHub URL 之类的引用查找对话线程，并按标题或匹配的对话线程查找任务。

## 原则

1. **聚焦重要的事。** 每个元素都回答三个问题之一，否则就删掉。数字只有在会改变监督者行为时才出现。
2. **定义精确。** 各类别有可检验的定义、彼此互斥且覆盖所有情况，就像任务阶段那样。标签说明一行在等谁、需要什么，而不是内部状态码。
3. **每个概念只有一个位置。** 来源状态属于 Source；对话线程和触发属于 Trigger；决策属于 Eval；任务属于 Execution。设置按其配置的概念分组。Overview 汇总这些页面并链接过去，而不是变成又一个详情视图。
4. **领域结构。** 面板使用领域术语。内部标识符只出现在折叠的细节里；在能解析出名称的地方，用名称替代标识符。
5. **状态诚实。** 计数等于它所链接列表的长度，任何状态都不与其他事实矛盾。
6. **默认安静。** 健康状态不占用额外空间。问题必须是可处理的；一次性的网络错误不算。需要人处理的行直接给出其操作。页面说明保持一句话，更多细节放在 (?) 提示框里。破坏性操作需要确认。
7. **控件一致。** 使用 DeepSeek Harness 的设计令牌和控件行为。同样的信息在整个面板中应当看起来一样。每个设置块有一条保存栏，只在有改动、保存进行中或保存失败时可见。
