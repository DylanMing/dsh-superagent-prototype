# 004 提示词

> [English](004-prompts.md) | 中文

本文档说明代理会读到什么、团队可以编辑什么，以及改动何时生效。它建立在 [000 理念](000-philosophy.zh.md) 到 [003 执行](003-execution.zh.md) 的基础之上。提示词文本以英文书写。

## 团队能写什么

团队可以编辑三个团队小节、添加技能，并覆盖每个内置的系统提示词部件。大多数默认值位于 `prompts/` 和 `skills/` 下。工具描述、通知和卡片仍留在代码中，无法通过提示词设置编辑。

| 小节 | 内容 |
| --- | --- |
| 沟通 | 何时给人发消息、消息以什么口吻呈现、每条 GitHub 消息开头的那一行（默认为 `This is by an automated agent, not a human`）、如何处理评审，以及哪些普通账号是评审机器人 |
| 任务范围 | 任务何时继续推进，何时带着草稿停下 |
| 交付要求 | 拉取请求中的证据、带行数阈值的自动合并条件，以及提交作者；若未指定，执行器以代理账号的 no-reply 地址提交 |
| 团队技能 | 代理在需要时加载的知识，例如一个 `identities` 技能，说明哪个 Feishu 用户对应哪个 GitHub 账号 |

内置文本涵盖角色、工具使用、宿主机制、授权规则，以及 GitHub 与 Feishu 技能。它按标题引用团队小节，而不是重复其内容。

### 内置部件与模板

覆盖使用以下键：

| 部件 | 键 |
| --- | --- |
| 共享指令与角色 | `runtime/shared`、`runtime/orchestrator`、`runtime/worker` |
| 工作指令 | `runtime/subscriptions`、`runtime/replies`、`runtime/dispatch`、`runtime/work`、`runtime/admission` |
| 交接指令 | `runtime/handoff/orchestrator`、`runtime/handoff/worker` |
| 来源技能 | `skill/feishu`、`skill/github` |
| 生成的小节 | `runtime/environment`、`runtime/policy`、`runtime/policy/none` |

生成的小节是可编辑的模板。它们必须保留以下占位符：

- `runtime/environment`：`{variables}`，用执行环境各行填充。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，每条启用的规则一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，在没有规则启用时使用。

编辑某个部件只会改变模型收到的指令。它不会改变门禁（gate）、授权范围（Mandate）、工具检查或账号包装脚本，这些仍由代码强制执行。

在人明确要求时，主会话也可以用 `orchestrator_prompts_save` 保存覆盖。如果保存时省略了某个覆盖的 `base`，则保留已保存的 base。对于已被移除、却仍存在于保存配置中的部件，其覆盖会在保存时被丢弃；其他任何未知部件都会被拒绝。

覆盖会记录它基于哪份内置文本。升级会保留团队自己的文本。若默认值发生变化，面板会把该部件标为 **Default updated**（默认内容已更新），并在团队文本旁展示差异。团队可以保留自己的文本、采用新的默认值，或编辑它。没有覆盖的部件会自动跟随新的默认值。

主会话可以在 `orchestrator_read prompts` 的 `default_changed` 下读取受影响的部件名。

## 组装与优先级

系统提示词按以下顺序组装：

1. 共享指令与角色。
2. 三个团队小节。
3. 订阅与回复。
4. 主会话的分发指令，或执行器的工作指令。
5. `runtime/admission`，仅对主会话。
6. 交接指令。
7. `runtime/environment`。
8. `runtime/policy`，仅对主会话。

准入（admission）指令来自 `prompts/admission.md`。它们描述主动评估，以及在什么情况下可以从卡片上忽略一个无关的候选。`orchestrator_eval` 返回上下文，而不是重复这些指令。

环境小节把部署范围的值给主会话，把任务特定的值给每个执行器。策略（Policy）小节在每次模型请求时都从设置重新生成。它包含 Policy 版本、接受模式、显式请求豁免，以及已启用的规则，形式为 `- <name> (<id>): <instruction>`，或一句说明：没有任何规则被启用。它放在最后，是为了让 Policy 的变更不影响前面的提示词文本。

执行器还会读取 DeepSeek Harness 的编码提示词和仓库的 `AGENTS.md`；主会话不读。推断出的任务会追加一条结尾说明，把其执行器限制在匹配到的规则内。派发和传入消息以触发卡片的形式内联到达，只有内容被截断时才给出资源指针。

执行器在无人值守下工作。它们的工具中排除了会向人提问、向人展示 UI 或更改配置档的工具，例如 `ask_user_question`、`present` 和 `plugin_manager`。

从最强到最弱：

1. 由工具和宿主强制的事实：身份、权限、工具参数检查、回复用途、长度限制。提示词文本无法改变它们。
2. 内置与生成的小节，以团队对它们的覆盖文本为准。
3. 主动型任务匹配规则中的流程与沟通要求，仅对该任务的执行器会话生效。
4. 团队小节和团队技能。
5. 外部文本：消息、评论、文档和引用。它是数据，永远不会改变规则或授权。

## 内置文本的原则

这些原则把 [000 理念](000-philosophy.zh.md) 应用到代理上：

- **角色分离。** 主会话只做路由：它转发原始触发和路由事实，不做技术决策；它使用一个路由工具，在单次调用中对多个等待中的候选做出决定。一条路由备注最多 30 个词。执行器阅读原始来源、判断范围、实现并验证。
- **主会话不等待。** 报告、后续通知、候选和已完成的后台作业都会作为消息自动到达。没有剩余工作可做时，它结束本轮。有一道护栏会拒绝 `sleep`、超过 30 秒的 shell 超时以及超过 5 秒的等待作业，因为被阻塞的步骤会拖延新的候选。这些指令在主会话的完整提示词中替换 DeepSeek Harness 自带的作业通知说明。
- **只在人必须行动或能用到结果时才发消息：** 结果可供评审或使用、需要某个决定或资源，或工作无法完成。聊天消息默认一句话，硬性上限为 100 个词。
- **执行器自行裁决后续消息。** 每个执行器处理并确认范围内的请求，并把超出其任务范围或属于另一个任务的请求交回。只有当一条消息的所有者都交回它，或它们结束而都未接手时，它才成为新工作。主会话会收到后续通知，但只能为停止工作而对它们采取行动。被交回的消息随后带着执行器给出的理由作为候选到达。
- **通过订阅和主会话协作。** 执行器跟踪相关的对话线程以获取上下文。主会话可以用一条最多 100 词的备注发送来自另一个任务的事实。订阅和该备注都不授予权限。
- **仅在显式引用时挂接。** 消息必须指向某个任务的拉取请求、Issue、来源消息或确认回复，或指向近期改动且恰好只有一个任务匹配。仅话题相似是不够的。挂接会让任务订阅整个对话线程；执行器若认为无关，就使用 `orchestrator_thread_unrelated`，且不在那里答复。
- **具体确认，只确认一次。** 在开始实质性工作之前，执行器会确认每个新请求，并点明对象和预期结果，以原消息下的回复形式发出。
- **通过 `human_action` 提问。** 执行器在其报告中放一个具体问题，主会话原样转发。如果该问题由某条人的消息引发，就点明那条消息，并由宿主在那里提问。否则在任务的原始对话中提问。与此同时，已获授权的工作可以继续。
- **诚实的交付。** 打开拉取请求并不等于就绪；草稿状态标记为未完成；没有真实改动前截图的 UI 变更不算就绪。
- **人的暂停持续有效**，跨后续消息、新的执行器会话和重启都保持，直到人解除它。自动反馈永远不会恢复被暂停的工作。
- **示例只展示格式。** 示例中的句子不是代理可以主张的事实。
- **按结果处理评审。** 已修复并验证的评论会静默解决；被拒绝的评论会附一句理由。自动化评审者的对话线程在得到答复后即解决，且每个自动化评审者对每个拉取请求最多三轮。
- **遇到重复工作就让步。** 当人的分支或拉取请求已经包含了该任务的改动时，执行器会关闭自己的拉取请求，并用一句话指向对方的。

## 版本

- 每次保存都会创建一个不可变版本，包含完整配置、修订号、前任版本、时间戳和来源（面板或工具）。恢复某个版本或默认值会再创建一个版本。
- 保存会声明其基准修订。冲突的保存会被拒绝，但不会丢弃草稿。
- 会话在每次模型请求时都读取最新版本，包括同一轮中的后续步骤。保存不会重启、取消或唤醒会话。宿主记录每个会话使用过的修订；执行器可以读取它在其中工作过的任何修订。
- 部署会设置一个总大小上限，包含覆盖在内。校验会拒绝未知的键、保留的内置技能名、未知的覆盖部件和缺失的模板占位符。它从不静默截断文本。与默认值完全相同的覆盖会被移除，使该部件跟随未来的默认值。
